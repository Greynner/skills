# prd-to-plan

Convert product requirements into an execution plan that can be implemented in small, verifiable steps.

## Workflow

1. Read the PRD and identify scope, assumptions, dependencies, and risks.
2. Inspect the target codebase when available before proposing changes.
3. Break the work into vertical slices that deliver user-visible progress.
4. For each phase, list files or areas likely to change, validation steps, and done criteria.
5. Identify decisions that must be made before implementation.
6. Keep the plan ordered so early phases reduce uncertainty.

## Output format

- Summary
- Assumptions
- Risks / unknowns
- Phased plan
  - Goal
  - Tasks
  - Validation
  - Done criteria
- Questions before starting

Prefer concrete tasks over vague milestones.
